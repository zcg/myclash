# 外观：系统材质 + 窗口内玻璃 + 亚克力纪律

Status: accepted

## Context

我们既要各平台的原生材质（macOS NSVisualEffect/Liquid Glass、Windows 11 Mica/Acrylic），
也要 MyGo 的窗口内玻璃（`plugins/glass`），还要亚克力的半透明工作卡与洗色控件。
前一版文档把「亚克力」当成唯一答案，去掉了玻璃与平台差异，这是错的：
系统材质透的是桌面/其他窗口，玻璃只透应用自己画的内容，亚克力是透明度与控件纪律——三者不是替代关系。

## Decision

1. **系统材质**（`WindowOptions.Vibrancy`）只用于 Ground：macOS 全系、Windows 11 22H2+；
   Linux 与 Windows 10 没有，Ground 实铺或渐变。
2. **窗口内玻璃**（`plugins/glass`）作为独立效果：工具条、浮层、悬浮窗、液态玻璃预设的工作卡、
   合并窗格、滚动边缘。它只采样窗口内已绘制内容；**不声称**在 Linux/Win10 透桌面。
3. **亚克力纪律**（Ground/Card/洗色/单一不透明度/禁用控件/guard/压力测试）平台无关地约束透明度与控件。
4. **三个预设**：液态玻璃（默认，系统材质 + 半透明卡）、透明（无材质，直接看穿）、
   实色。不暴露模糊档位，避免「档位看不出变化」。
5. **唯一不透明度入口**是工作卡：作用于 `CardFill`；范围 0–100%，0% 完全透明。
6. 设置页按平台显示能力：无系统材质时说明液态玻璃只剩半透明卡；不显示「假磨砂」选项。

## Considered Options

- 只做亚克力（上一版）：失去玻璃与 macOS 26 的 Liquid Glass，Linux 也变成实色。
- 只做玻璃插件：Linux/Win10 没有桌面磨砂，且长文本/表格不适合玻璃。
- 每个平台一套完全不同的界面：维护与验收成本过高。

## Consequences

- 外观有平台差异，但结构、控件与交互一致；差异只在材质与玻璃的可用性。
- 需要两套测试：亚克力 guard/洋红压力，以及玻璃的采样边界（Linux/Win10 截图）。
- 玻璃与系统材质同时出现时，玻璃只用于小面积浮层；大面积优先半透明卡，避免互相抢戏。
- 性能降级明确：实色预设 / 无系统材质 / 减少透明度。
- 任何「玻璃透桌面」的文案或承诺都是缺陷，验收时直接拒绝。
