# 内核只随应用更新；运行模式二选一

Status: accepted

## Context

独立外部内核（ADR-0009）能单独升级 mihomo，但会多一个进程、多一套下载/校验/回滚/TUN 监督链路，
而作者已明确接受「内核随应用版本更新」。另一方面，轻量模式要让 UI 关闭后代理继续，必须有一个
没有 UI 的进程持有内核——这是操作系统回收内存的单位决定的，无法在单进程里既释放 UI 又保留内核。

## Decision

1. **内核只做 bundled**：mihomo 编译进应用，随应用更新；支持重启（`executor.Shutdown` + 重新 `hub.Parse`），
   不提供独立内核下载/切换。M1–M3 不实现 external core。
2. **两种运行模式都实现，运行时互斥**：
   - **standard（默认）**：GUI 内嵌内核，拥有托盘与单实例锁；一个进程，内存最低。
   - **lightweight**：`myclash --agent` 拥有内嵌内核、托盘、系统代理/TUN 与单实例锁；GUI 附着为前端，
     关闭窗口即退出 GUI，Agent 继续代理。
3. 模式在设置中选择；切换时停止内核并按新模式重启应用，接受数秒断流。再次打开 GUI 时附着现有 Agent，
   不重启内核。
4. 托盘与状态写入归内核所有者（standard 是 GUI，lightweight 是 Agent）；同一时刻只有一个所有者。
5. 外部内核与独立更新推迟到 M3 之后；若重启，需要新的 ADR，不复用旧方案。

## Considered Options

- 只做标准模式：最简单，但关闭窗口后无法在释放 UI 内存的同时继续代理。
- 只做轻量模式：日常也常驻两进程，违背低内存目标。
- 两种模式并存但允许同时运行：两个内核、两个托盘、状态双写，不可接受。
- 保留 external：与「内核随应用更新」的取舍冲突，且显著扩大测试面。

## Consequences

- 内核更新 = 应用更新；发布说明必须写清 mihomo 版本。用户不能单独回退内核，除非回退应用。
- 轻量模式是 opt-in：窗口打开时 GUI + Agent 两进程，内存高于标准；关窗后只剩无 UI 的 Agent。
- 状态单写者、托盘归属、附着/脱离协议仍是必须实现的复杂度，但不再有外部内核的供应链。
- 测试矩阵收敛为：standard / lightweight × bundled ×（TUN 开/关）。
- ADR-0009 标记为 superseded；`core_source`、外部内核页面与相关错误类型从文档与计划中移除。
